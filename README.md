# PDF Ingestion Pipeline — Scholaria AI

خط معالجة يحوّل ملفات PDF (عربي/إنجليزي مختلط) إلى محتوى قابل للبحث الدلالي، مخزّن في Qdrant وجاهز لطبقة RAG.

مبني وفق **وثيقة المواصفات الفنية لمنظومة الذكاء الاصطناعي في سكولاريا — الإصدار 1.0**.

---

## نظرة عامة

```
PDF
 ↓  استخراج (text layer + OCR fallback)
 ↓  تنظيف (تطبيع عربي + boilerplate + فلتر OCR)
 ↓  تقسيم دلالي (semantic chunking)
 ↓  إثراء بالسياق + metadata
 ↓  embeddings (bge-m3)
 ↓  Qdrant (dense + sparse)
 ↓
بحث: Hybrid (RRF) → Reranker → أفضل 3-5
```

## المكوّنات

### الاستخراج — `pdf_extractor.py`

يقرأ النص مرتّبًا حسب موضعه البصري وليس ترتيب إدراجه في الملف:

```python
blocks.sort(key=lambda b: (round(b[1] / 20), b[0]))
```

ضروري للعروض التقديمية، حيث كل عنصر صندوق نص منفصل والترتيب الأصلي عشوائي.

**OCR كـ fallback:** الصفحات التي يقل نصها المستخرج عن 50 حرفًا تُحوّل إلى صورة 200 DPI وتُقرأ بـ Tesseract (`ara+eng`). هذا يتجنب معالجة الملف كاملًا بالـ OCR.

### التنظيف — `processing.py`

**تطبيع النص العربي:** النص العربي في ملفات PDF يُخزَّن غالبًا كـ presentation forms:

```
اﻹدارة اﻟﺮﺷﻴﻘﺔ  →  الاداره الرشيقه
```

`unicodedata.normalize("NFKC")` تعيده لشكله الطبيعي. بدون هذه الخطوة تكون الـ embeddings عديمة القيمة.

كذلك: إزالة bidi controls، التشكيل، التطويل، وتوحيد `أ/إ/آ → ا` و `ى → ي` و `ة → ه`.

**فلتر جودة OCR** على مستويين — يقيس نسبة الكلمات "اليتيمة" (حرف أو حرفين) كمؤشر على فشل التعرّف:

- سطر بسطر: يُزيل السطور الرديئة ويُبقي السليمة
- الصفحة كاملة: تُرفض إذا بقي المحتوى ضعيفًا

**إزالة boilerplate:** تلقائيًا للسطور المتكررة عبر الصفحات، وبأنماط محددة للنصوص الملتصقة داخل المحتوى.

### التقسيم الدلالي — `semantic_chunker.py`

الحدود تُحدَّد بقياس التشابه بين وحدات النص، لا بأنماط شكلية:

```python
sims = [np.dot(vectors[i], vectors[i+1]) for i in range(len(vectors)-1)]
threshold = np.percentile(sims, 25)
```

العتبة **نسبية لكل مستند** — تُحسب من الملف نفسه. هذا يجعل الخوارزمية تعمل على أي بنية دون افتراضات مسبقة.

**fallback:** الوحدات التي تتجاوز `max_chars` تُقسَّم بالحجم مع overlap، لأن نماذج الـ embedding لها حد أقصى للسياق، ولأن الـ vector الواحد لا يمثّل عدة صفحات بدقة.

### الـ Metadata — `schema.py`

15 حقلًا إلزاميًا وفق البند 6.4:

```json
{
  "tenantId": "dev-tenant",
  "courseId": 1,
  "contentId": 1005,
  "contentType": "Lecture",
  "language": "ar",
  "pageNumber": 58,
  "contentVersion": 1,
  "published": true,
  "checksum": "sha256..."
}
```

**vectorId حتمي** — مشتق من `contentId:version:chunkIndex` عبر UUID5. نفس المدخلات تنتج نفس المعرّف دائمًا، فإعادة التشغيل تُحدِّث بدل أن تُكرِّر.

### الفهرسة التدريجية — `registry.py`

| الحالة | السلوك |
|---|---|
| ملف جديد | يُفهرس، `version = 1` |
| ملف مُعدَّل | `version + 1`، معرّفات جديدة |
| ملف بلا تغيير | يُتخطى — صفر تكلفة |

يعتمد على checksum (SHA-256) لكل ملف. البند 16.2 يطلب عدم إعادة الـ embedding عند ثبات الـ checksum.

### البحث — `vector_store.py`

بحث hybrid يدمج مسارين عبر Reciprocal Rank Fusion:

- **dense** (bge-m3) — يلتقط المعنى
- **sparse** (BM25) — يلتقط المصطلحات والأسماء

كلا المسارين يُطبَّق عليهما فلتر العزل قبل حساب التشابه:

```python
Filter(must=[tenantId, courseId, published])
```

### إعادة الترتيب — `reranker.py`

يستقبل 20 مرشحًا ويعيد أفضل 3-5، وفق البند 6.5.

يتضمن **fallback** — عند فشل الـ API يعود الترتيب الأصلي، فلا تتعطل الخدمة (البند 5.4).

## القيود المعروفة

**جودة الـ OCR العربي محدودة.** Tesseract محرك تقليدي يعمل على مستوى الحرف دون فهم للسياق، والعربي أصعب عليه لاتصال الحروف وتغيّر أشكالها. موثّق كخطر في البند 21.

**شرائح بلا نص كافٍ.** بعض الشرائح محتواها الأساسي رسوم بيانية، فالنص المستخرج مجرد عنوان. لا تُحلّ بتغيير التقسيم — جُرِّبت ثلاث طرق.

**نسبة fallback في التقسيم مرتفعة.** الوحدات الدلالية في المحتوى التعليمي تمتد 5-15 صفحة، أكبر من حد السياق. الحل المقترح: تقسيم دلالي على مستويين (صفحات ثم فقرات).

**الـ reranker يعتمد على parsing نص حر.** البند 5.5 يحذّر من ذلك. طُبِّق validation و fallback، لكن reranker متخصص أنسب للإنتاج.
