# Scholaria AI — Files RAG Pipeline

خط معالجة يحوّل ملفات المقرر (PDF بمحتوى عربي/إنجليزي مختلط) إلى إجابات مدعومة بمراجع دقيقة.

مبني وفق **وثيقة المواصفات الفنية لمنظومة الذكاء الاصطناعي في سكولاريا — الإصدار 1.0**.

هذا الـ branch يغطي **مسار الملفات**. مسار الفيديو في `video-rag`.

---

## نظرة عامة

```
PDF → استخراج (+OCR) → تنظيف → تقسيم دلالي → metadata → embeddings → Qdrant
                                                                         ↓
              سؤال → Hybrid Search → Rerank → LLM → إجابة + مراجع
```

---

## البنية

```
ingestion/
├── files/
│   ├── pdf_extraction.py     استخراج النص + OCR fallback
│   ├── file_chunking.py      تطبيع + تنظيف + تقسيم دلالي
│   ├── registry.py           فهرسة تدريجية بالـ checksum
│   └── file_pipeline.py      تنسيق المسار
└── shared/                   ← مشترك مع مسار الفيديو
    ├── schema.py             الـ payload الموحّد
    ├── embedding.py          bge-m3 + BM25
    ├── qdrant_upsert.py      التخزين
    └── storage.py            حفظ للمراجعة

retrieval/       search · filtering · reranking
generation/      answerer
ask.py           واجهة تفاعلية للاختبار
```

⚠️ ملفات `shared/` يجب أن تكون **نسخة واحدة بالحرف** بين المسارين. أي اختلاف في الموديل أو الأبعاد يجعل الـ vectors غير قابلة للمقارنة.

## التشغيل

### المتطلبات

- Python 3.10+
- **Tesseract OCR 5.x** مع حزمة اللغة العربية ([installer](https://github.com/UB-Mannheim/tesseract/wiki))

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

### الإعداد

انسخ `.env.example` إلى `.env`:

```
OPENROUTER_API_KEY=your_key_here
RERANK_MODEL=qwen/qwen3-8b
ANSWER_MODEL=qwen/qwen3-vl-32b-instruct
```

⚠️ مسارات التخزين ثابتة في الكود (`F:\hf_cache`, `F:\fastembed_cache`, `F:\pdf_tmp`) — عدّلها حسب جهازك.

ضع ملفات PDF في `data/`.

### التشغيل

```bash
python -m ingestion.files.file_pipeline    # الفهرسة كاملة
python ask.py                              # واجهة تفاعلية
python test_qdrant_search.py               # البحث + اختبار العزل
python sync.py                             # مزامنة المحذوفات
```

## قرارات أساسية

**تطبيع النص العربي** — النص في PDF يُخزَّن كـ presentation forms (`اﻹدارة اﻟﺮﺷﻴﻘﺔ` → `الاداره الرشيقه`). بدون `NFKC` تكون الـ embeddings عديمة القيمة.

**ترتيب القراءة البصري** — العروض التقديمية تُرجع النص بترتيب الإدراج لا الترتيب المرئي، فيُعاد ترتيبه بالإحداثيات.

**OCR على النص المفيد** — الفحص يتم بعد إزالة الـ boilerplate. صفحة بها 190 حرفًا كلها حقوق نشر كانت تمر دون OCR بينما محتواها الحقيقي (1719 حرفًا) في صورة.

**اكتشاف الترميز المكسور** — بعض الملفات تسجّل الخط العربي بترميز لاتيني فيرجع النص مشوّهًا (`دوره الح‚اه التsب„Rه`). هذه الحالة تمر من كل الفلاتر التقليدية، فلها كاشف مخصص و OCR إجباري.

**الصفحة هي وحدة الـ chunk** — والترابط الدلالي يُحفظ في `topicId` بدل دمج الصفحات. هذا يحقق vector دقيقًا ومرجع صفحة لا لبس فيه.

**`pageNumber` = الصفحة صاحبة أكبر نصيب من النص** لا أول صفحة. الأخير كان يعطي مراجع خاطئة.

**vectorId حتمي** — مشتق من `contentId:version:chunkIndex`، فإعادة التشغيل تُحدِّث بدل أن تُكرِّر (البند 6.2).

**بحث hybrid** — dense للمعنى + BM25 للمصطلحات، مدموجين بـ RRF. الفلتر (`tenantId`, `courseId`, `published`) يُطبَّق على المسارين قبل حساب التشابه.

## قياس أحجام الـ chunks

البند 6.3 ينص على أن الأرقام "إعدادات بداية تُضبط بالقياس". طُبِّق على أربعة إعدادات بنفس مجموعة الأسئلة:

| الحد الأدنى | overlap | chunks | نتائج دقيقة |
|---|---|---|---|
| 40 token | ❌ | 80 | 4/5 |
| 180 token | ✅ | 47 | 2/5 |
| 350 token (الوثيقة) | ✅ | 37 | 2/5 |
| **40 token** | **✅** | **59** | **4/5** |

النتيجة عكسية: تكبير الـ chunk **قلّل** الدقة. الشريحة ≈150 token وهي وحدة معنى مكتملة؛ الدمج القسري يخلط مواضيع في vector واحد.

**توصية:** إضافة profile للعروض التقديمية في البند 6.3.

## القيود المعروفة

- **جودة OCR العربي محدودة** — Tesseract بلا فهم سياقي (موثّق كخطر في البند 21)
- **الـ embedding يُنفَّذ مرتين** — في التقسيم وفي الفهرسة. مع API مدفوع تصبح تكلفة مضاعفة
- **مسارات التخزين ثابتة في الكود** — يجب نقلها للإعدادات
- **`tenantId` يُمرَّر كمعامل** — في النظام الفعلي يجب اشتقاقه من Authentication Claims (البند 15 — SEC-002)

## للدمج مع مسار الفيديو

**ملفات متطابقة بالحرف:**
```
ingestion/shared/schema.py
ingestion/shared/embedding.py
ingestion/shared/qdrant_upsert.py
```

وكذلك `normalize_arabic` في `file_chunking.py` — التطبيع المختلف ينتج vectors مختلفة لنفس النص.

**نقاط متفق عليها:**

| البند | القيمة |
|---|---|
| Embedding model | `BAAI/bge-m3` |
| الأبعاد | 1024 |
| Distance | COSINE |
| Sparse model | `Qdrant/bm25` |
| `contentId` | ملفات 1000+ · فيديو 2000+ |

⚠️ نطاقات `contentId` منفصلة ضرورية — الـ `vectorId` مشتق منه، والتصادم يجعل مصدرًا يمسح الآخر.
